# DP 音频元数据传输：SDP 与 MAF

> **SDP** = Secondary Data Packet（辅助数据包），DP 链路层除了传视频和音频采样外，还通过 SDP 传输 InfoFrame、音频采样包等辅助数据。
>
> **MAF / MSA** = Main Stream Attribute（主流属性），Framer 在垂直消隐期发送的控制符号序列，携带视频时序、音频采样率/位宽/通道数等信息。Audio InfoFrame 全填 0（STREAM）时，sink 就转去读 MAF 里的真实参数。
>
> InfoFrame SDP 是指路牌（"去看 MAF"），MAF 是目的地（"这里是 48kHz / 2ch / 24bit LPCM"）。

---

## 一、两条物理上分离的通道

DP 音频的采样值和元数据走的是**两条物理上完全独立的路径**：

```
                        CDN-DP 控制器
                        ┌──────────────────────────────────────────────┐
                        │                                              │
I2S/SPDIF ─────────────┤  ① 采样值路径 (FIFO)                           │
  BCK+LRCK+DATA         │     AIF → 解码器 → SMPL2PKT → FIFO            │
                        │                    ↓                          │
                        │              音频采样包                        │
                        │               (Audio Sample Packets)           │
                        │                    │                          │
                        │                    ├────▶ DP Main Link ──▶ Sink
                        │                    │
                        │  ② 元数据路径 (SDP + MAF)                      │
                        │     SDP: Audio InfoFrame                       │
                        │       ├─ 采样率 (或"参考流头")                   │
                        │       ├─ 位宽 (或"参考流头")                   │
                        │       ├─ 通道数 (或"参考流头")                   │
                        │       └─ 编码类型 / 音箱分配                    │
                        │                    │                          │
                        │     MAF: Stream Header                         │
                        │       ├─ 真实采样率 ← COM_CH_STTS_BITS 寄存器   │
                        │       ├─ 真实位宽   ← AUDIO_SRC_CNFG 寄存器    │
                        │       └─ 真实通道数 ← AUDIO_SRC_CNFG 寄存器    │
                        │                    │                          │
                        │                    ├────▶ DP Main Link ──▶ Sink
                        │                                              │
                        └──────────────────────────────────────────────┘
```

**关键结论**：FIFO 错位只污染采样值。元数据走的是 `SOURCE_PIF_DATA_WR`（SDP）和硬件寄存器（MAF），从未经过 FIFO。

## 二、SDP：Audio InfoFrame 的构造和发送

### 2.1 SDP 包结构

DP 的 Secondary Data Packet 头部固定 4 字节：

```
Audio InfoFrame SDP:
┌──────┬──────┬──────┬──────┬────────────────────────────────────┐
│ HB0  │ HB1  │ HB2  │ HB3  │        DB0 ~ DB27 (28 bytes)       │
│ 0x00 │ 0x84 │ 0x1B │ 0x48 │    CEA-861 Audio InfoFrame 内容     │
└──────┴──────┴──────┴──────┴────────────────────────────────────┘
        ↑             ↑
  类型 = Audio    DB 长度 = 0x48 (72 bits, 每 4-byte DB 子包 × 18)
   InfoFrame
```

### 2.2 驱动中的构造过程

[`cdn_dp_setup_audio_infoframe()`](kernel/drivers/gpu/drm/rockchip/cdn-dp-core.c#L871)：

```
① 构造 SDP 头部:
   HB0 = 0
   HB1 = 0x84 (HDMI_INFOFRAME_TYPE_AUDIO)
   HB2 = 0x1B (版本号)
   HB3 = 0x48 (DB 区数据长度)

② 构造 CEA-861 Audio InfoFrame:
   hdmi_audio_infoframe_init(&frame)
   frame.coding_type      = HDMI_AUDIO_CODING_TYPE_STREAM    (= 0)
   frame.sample_frequency = HDMI_AUDIO_SAMPLE_FREQUENCY_STREAM (= 0)
   frame.sample_size      = HDMI_AUDIO_SAMPLE_SIZE_STREAM      (= 0)
   frame.channels         = 0

③ 打包:
   hdmi_audio_infoframe_pack(&frame, buffer, 14)
   → buffer 内容 = [1-byte CEA Header][3-byte InfoFrame Data...]

④ 拷贝到 SDP 的 DB 区域 (跳过 CEA Header):
   memcpy(infoframe_sdp.db, buffer + 1, 13)

⑤ 通过 Source PIF 发送:
   cdn_dp_infoframe_set(dp, 0, &infoframe_sdp, sizeof(infoframe_sdp), 0x84)
```

### 2.3 Source PIF 的写入过程

[`cdn_dp_infoframe_set()`](kernel/drivers/gpu/drm/rockchip/cdn-dp-reg.c#L1028)：

```c
// ① 逐 32-bit 写入 SDP 数据到 PIF 内部 SRAM
for (idx = 0; idx < length; idx++)
    writel(cpu_to_le32(*packet++), dp->regs + SOURCE_PIF_DATA_WR);

// ② 指定写入地址 (entry_id=0)
writel(entry_id, dp->regs + SOURCE_PIF_WR_ADDR);

// ③ 触发 HOST 写入请求
writel(HOST_WR, dp->regs + SOURCE_PIF_WR_REQ);

// ④ 分配包类型 (0x84 = Audio InfoFrame) 和地址
writel(ACTIVE_IDLE_TYPE(1) | TYPE_VALID |
       PACKET_TYPE(type) | PKT_ALLOC_ADDRESS(entry_id),
       dp->regs + SOURCE_PIF_PKT_ALLOC_REG);

// ⑤ 使能包分配写
writel(PKT_ALLOC_WR_EN, dp->regs + SOURCE_PIF_PKT_ALLOC_WR_EN);
```

SDP 被写入 PIF 后，firmware 在每帧的垂直消隐期按需调度发送。**SDP 和 FIFO 不在同一个地址空间**——PIF 的寄存器基址是 0x30800，而 FIFO 在 0x30088。

## 三、MAF：Stream Header 中的真实参数

### 3.1 为什么 InfoFrame 全填 0

`coding_type = 0`、`sample_frequency = 0`、`sample_size = 0`、`channels = 0` 全部等于 `STREAM`（0）。这是标准行为——意思是"**去 MAF 里查真实值**"：

```
Audio InfoFrame SDP:               MAF (Stream Header):
  coding_type = 0 (STREAM)  ──→  "去 MAF 查真实的 coding_type"
  sample_freq = 0 (STREAM)  ──→  "去 MAF 查真实的 sample_rate"
  sample_size = 0 (STREAM)  ──→  "去 MAF 查真实的 sample_width"
  channels = 0              ──→  "去 MAF 查真实的通道数"
  channel_allocation = x    ──→  直接使用 (音箱位置分配)
```

MAF 的内容由 firmware/硬件根据驱动写入的寄存器值自动生成。

### 3.2 采样率是怎么进入 MAF 的

[`cdn_dp_audio_config_i2s()`](kernel/drivers/gpu/drm/rockchip/cdn-dp-reg.c#L964-L995) 中的采样率编码：

```
audio->sample_rate  →  SAMPLING_FREQ 值  →  ORIGINAL_SAMP_FREQ 值
─────────────────────────────────────────────────────────────────
     32000                   3 (0011)               0xc (1100)
     44100                   0 (0000)               0xf (1111)
     48000                   2 (0010)               0xd (1101)
     88200                   8 (1000)               0x7 (0111)
     96000                  10 (1010)               0x5 (0101)
    176400                  12 (1100)               0x3 (0011)
    192000                  14 (1110)               0x1 (0001)
```

写入 `COM_CH_STTS_BITS` 寄存器（0x30008）：

```
位布局:
  [31:28]  ORIGINAL_SAMP_FREQ  (4 bits) — 原始采样频率指示
  [27:24]  保留
  [23:20]  保留
  [19:16]  SAMPLING_FREQ       (4 bits) — 采样频率
  [15:8]   保留
  [7:0]    保留, 但会被 |= 4 (BIT(2))

例, 48000 Hz:
  SAMPLING_FREQ(2)  = (2 << 16)  = 0x00020000
  ORIGINAL_SAMP_FREQ(0xd) = (0xd << 24) = 0x0D000000
  |= 4                           = 0x00000004
  ─────────────────────────────────────────────
  COM_CH_STTS_BITS              = 0x0D020004
```

Firmware 读取这个寄存器的值，填入 MAF 的对应字段。Sink 收到 MAF → 知道音频是 48kHz。

## 四、什么情况下采样率会被错报

### 4.1 核心前提

采样率元数据 = `COM_CH_STTS_BITS` 寄存器的当前值。这个寄存器只在 `cdn_dp_audio_config_i2s()` **或** `cdn_dp_audio_config_spdif()` 中写入。如果这两个函数没有被调用，寄存器停留在**上一次的值**或**硬件默认值**。

### 4.2 场景 A：重插后 hw_params 未重新执行

```
1. DP 插入 → 正常 48kHz 播放
   COM_CH_STTS_BITS = 0x0D020004 (48kHz)

2. DP 拔出 → cdn_dp_disable() → 时钟关, 寄存器可能丢失或保留
   (取决于是否完全掉电)
   
3. DP 重插 → cdn_dp_enable() → hardware reset
   所有寄存器复位到默认值 → COM_CH_STTS_BITS = 0x00000000

4. ALSA 未重调 hw_params (jack 回调断裂, stream 一直开着)
   COM_CH_STTS_BITS 保持 = 0x00000000

5. Firmware 读 COM_CH_STTS_BITS:
   SAMPLING_FREQ field (bits 19:16) = 0
   → firmware 用 SAMPLING_FREQ(0) 查表 → 44.1kHz

6. I2S 实际 LRCK = 48kHz (CPU DAI 未停)
   
7. Sink 收到:
   元数据: "44.1kHz"
   实际数据: 48kHz 的 I2S 采样流
   → 时钟不匹配 → 播放速率异常或缓冲区问题
```

### 4.3 场景 B：寄存器残留在前一次配置

**这是 "48kHz → 88.2kHz" 的直接原因。**

```
1. 上一轮播放: 88.2kHz
   COM_CH_STTS_BITS = SAMPLING_FREQ(8) | ORIGINAL_SAMP_FREQ(7) | 4
                    = (8 << 16) | (7 << 24) | 4
                    = 0x07080004

2. DP 拔出 → 时钟关, 但寄存器在 retention 域 → 值保留
   或: register file 没有经过 reset → 值不变

3. DP 重插 → clock_reset() 不复位音频寄存器
   (clock_reset 只写 *_CAR 时钟使能寄存器, 不碰 audio decoder 寄存器)
   COM_CH_STTS_BITS 仍为 0x07080004

4. ALSA 重新 open, hw_params(48000)
   → 但如果 dp->active 尚未 true → hw_params 被静默跳过
   → 或: ALSA 根本不知道重插了 (jack 回调断裂), 没调 hw_params
   → COM_CH_STTS_BITS 没有更新

5. Firmware 读到残留值:
   SAMPLING_FREQ = 8 → 88.2kHz
   ORIGINAL_SAMP_FREQ = 7

6. I2S 实际 = 48kHz, 元数据 = 88.2kHz
   → Sink 以 88.2kHz 时钟去解码 48kHz 数据
   → 数据流入速度不够 → 缓冲区欠载 → 卡顿 / 爆音
```

**"48kHz 被错报为 88.2kHz" 的本质**：不是硬件算错了，而是**上一轮 88.2kHz 的配置残留在寄存器里，本轮 48kHz 的配置从未被写入**。

更一般地说：

```
任何上一轮的采样率都可能残留在寄存器中:

  上一轮 32000 → SAMPLING_FREQ(3) → 残留 3  → 错报为 32kHz
  上一轮 44100 → SAMPLING_FREQ(0) → 残留 0  → 错报为 44.1kHz (和默认值一样)
  上一轮 48000 → SAMPLING_FREQ(2) → 残留 2  → 错报为 48kHz (恰好相同)
  上一轮 88200 → SAMPLING_FREQ(8) → 残留 8  → 错报为 88.2kHz ← 最典型
  上一轮 96000 → SAMPLING_FREQ(10) → 残留 10 → 错报为 96kHz
  上一轮 192000 → SAMPLING_FREQ(14) → 残留 14 → 错报为 192kHz
```

### 4.4 场景 C：时钟测量寄存器未配置

[`cdn_dp_audio_config()`](kernel/drivers/gpu/drm/rockchip/cdn-dp-reg.c#L1056-L1060) 还写两个时钟测量寄存器：

```c
cdn_dp_reg_write(dp, CM_LANE_CTRL, LANE_REF_CYC);  // lane 参考周期 = 0x8000
cdn_dp_reg_write(dp, CM_CTRL, 0);                   // 清除 clock meter 控制
```

CDN-DP 内部有硬件时钟测量单元（`CM_I2S_CTRL` 0x0a04、`CM_SPDIF_CTRL` 0x0a08），用于测量 I2S LRCK / SPDIF 帧速率，辅助 firmware 确定真实的音频采样率。

如果 `audio_config()` 被跳过，这两个寄存器保持在默认值：

```
CM_LANE_CTRL = 默认值 (不是 LANE_REF_CYC = 0x8000)
CM_CTRL      = 默认值
```

Firmware 读取时钟测量结果时，参考时钟可能不正确 → 自动检测到的采样率与实际不符 → 即使 COM_CH_STTS_BITS 后来被写入正确值，firmware 可能用测量值覆盖 → MAF 中的采样率错了。

## 五、对比：什么时候不会错

```
正常路径 (所有原则都被满足的情况下):

  HPD↑ → event_work → dp->active=true → drm hotplug → userspace modeset
  → sink 声卡出现 → PipeWire 打开 PCM → hw_params(48000)
  → cdn_dp_audio_config()
    → COM_CH_STTS_BITS = 0x0D020004 (正确)
    → CM_LANE_CTRL = LANE_REF_CYC    (正确)
    → CM_CTRL = 0                    (正确)
  → Firmware 构造 MAF: sample_rate = 48000 ✓
  → Sink 解析 MAF: 48kHz ✓
  → DAC 以 48kHz 时钟播放 ✓
```

错报只在**一个条件**下发生：`audio_config()` 没有在硬件 reset 后重新执行，但音频数据已经通过 I2S/SPDIF 在流动。根源是文档 [12-dp-audio.md](12-dp-audio.md) 中的**原则 4**（硬件复位→无条件重配）被违反。

## 六、和 FIFO 错位的关系

```
                      FIFO 错位                    |     元数据错报
──────────────────────────────────────────────────┼───────────────────────
受影响的数据         采样值 (裸 PCM)                 |     采样率、位宽、通道数
传输通道             FIFO → SMPL2PKT → 音频包       |     SDP → MAF → 流头
后果                 爆鸣 / 无声                     |     播放速率异常 / sink 拒绝解码
                      (值是垃圾, sink 照样当 LPCM 播)      (sink 时钟与实际数据不匹配)
恢复方式             AUDIO_SW_RST                   |     重新调 audio_config()
```

两者可以同时发生：重插后 hw_params 被跳过 → FIFO 未复位（爆鸣/无声） + COM_CH_STTS_BITS 未更新（速率错报）。
