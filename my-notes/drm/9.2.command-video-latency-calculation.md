# Command Mode vs Video Mode 延迟计算

> 计算对象：从 Userspace 提交新 framebuffer → 该帧最后一像素在屏幕上可见 的时间。

---

## 1. 公共参数

所有模式共用的物理量，以 1080×1920 @ 60fps, 4-lane DSI @ 1Gbps/lane, 24bpp 为例：

| 符号 | 含义 | 计算公式 | 数值 |
|------|------|---------|------|
| `T_fb_swap` | 用户提交 → DRM atomic commit 完成 → 硬件可读取新帧 | 等待 VBLANK，平均 0.5 帧 | **8.3ms** |
| `T_panel_scan` | Panel 从 GRAM（或直通路径）把一行行像素扫到屏幕的物理时间 | 1 / fps | **16.7ms** |
| `T_frame_transfer` | 一整帧通过 DSI 链路传输的纯带宽时间 | `h × v × bpp / (lanes × lane_rate)` | **12.5ms** |
| `T_seg_transfer` | 1/3 帧的传输时间 | `T_frame_transfer / 3` | **4.2ms** |
| `T_seg_scan` | Panel 扫描 1/3 帧的时间 | `T_panel_scan / 3` | **5.6ms** |
| `T_te_wait` | 等待 TE 信号允许写入 GRAM | 0~T_panel_scan，取决于 TE 相位 | **0~16.7ms** |

---

## 2. Video Mode

Video Mode 没有 GRAM 中转。像素从 DDR 读出后，逐行通过 DSI 发到 Panel 列驱动器，**一行到一行显**。

```
DDR ──→ Display Controller ──→ DSI ──→ Panel 列驱动器（直接）
```

一帧时间线（每行实时流水）：

```
├─ Line 0: 读出 → DSI Tx → Panel 显示 ─┤
├─ Line 1: 读出 → DSI Tx → Panel 显示 ─┤
├─ Line 2: 读出 → DSI Tx → Panel 显示 ─┤
...
└─ Line 1919: 读出 → DSI Tx → Panel 显示 ─┘
```

**最后一像素可见延迟**：

```
T_video = T_fb_swap + T_panel_scan

        = 8.3 + 16.7 = 25ms ≈ 1.5 帧
```

**为什么没有 `T_frame_transfer` 项**：Video Mode 的传输和扫描是同一过程——发完一行就是扫完一行，`T_panel_scan` 已经包含了所有行的传输和扫描。没有"先存后取"。

**波动区间**：8.3~33.4ms（0.5~2 帧），取决于 `T_fb_swap` 的 VBLANK 相位和 `T_te_wait` 是否参与（Video Mode 无需等 TE）。

---

## 3. Command Mode — 全 GRAM

Panel 内置一整帧容量的 GRAM。Host 先把整帧写入 GRAM，Panel 再独立从 GRAM 扫到屏幕。

```
DDR ──→ Display Controller ──→ DSI ──→ Panel GRAM ──→ 列驱动器
                                      └── 中转站 ──┘
```

### 3.1 收完再扫（最坏情况）

Panel 必须等整帧写入 GRAM 之后才开始扫描：

```
├─────────── 写 GRAM (12.5ms) ───────────┤
                                         ├────── 扫 GRAM (16.7ms) ──────┤
```

```
T = T_fb_swap + T_frame_transfer + T_panel_scan + T_te_wait
  = 8.3 + 12.5 + 16.7 + 8.3(avg TE wait)
  ≈ 46ms ≈ 2.8 帧
```

### 3.2 边收边扫（理想情况）

Panel 可以在接收首行数据的同时就开始扫描（GRAM 支持并发读写）：

```
├── 写 GRAM (12.5ms) ────────────────┤
├────── 扫 GRAM (16.7ms) ────────────┤
        ↑
        首行写入后立即开始扫，
        写入和扫描后面各行重叠
```

**关键**：`T_frame_transfer` (12.5ms) < `T_panel_scan` (16.7ms)，所以传输不拖扫描后腿。

```
T = T_fb_swap + max(T_frame_transfer, T_panel_scan) + T_te_wait
  = 8.3 + 16.7 + 8.3(avg TE wait)
  ≈ 33ms ≈ 2 帧
```

这里的 `max()` 是核心：哪个时间长就取哪个，因为写和扫是重叠的。`T_panel_scan` 更长，它就是瓶颈。

---

## 4. Command Mode — 1/3 RAM

Panel 的 GRAM 只有 1/3 帧容量。一帧数据必须分三段发送，每段写入 GRAM 后才能被扫描。

### 4.1 硬件约束

一帧在屏幕上分成三段：

```
屏幕
┌────────┐ 段1（顶部）  扫描线从顶走到底
├────────┤ 段2（中部）  物理时间 = T_panel_scan(整帧) = 16.7ms
├────────┤ 段3（底部）  最后一像素在这里
└────────┘
            ↑
            同一时刻 GRAM 只能存其中一段
```

**不变量**：无论采用什么调度策略，最后一像素在屏幕最底部，扫描线要走过整帧才能到。所以 **`T_panel_scan(整帧)` 永远参与总延迟**。

### 4.2 方式 A：串行

写完一段→扫这一段→写下一段，完全不重叠。

```
├WR1┤├── RD1 ──┤├WR2┤├── RD2 ──┤├WR3┤├── RD3 ──┤
    ↑           ↑           ↑           ↑
    写段1       扫段1       写段2       扫段2 ...
```

```
T_A = T_fb_swap + 3 × (T_seg_transfer + T_seg_scan)
    = 8.3 + 3 × (4.2 + 5.6)
    = 8.3 + 29.4
    = 37.7ms ≈ 2.3 帧
```

### 4.3 方式 B：流水线

Panel 硬件支持**两块独立的 GRAM Bank 交替读写**（或双端口 RAM）：写 Bank B 的同时可以扫 Bank A。

```
传输: ├WR1┤├─── WR2 ───┤├─── WR3 ───┤
扫描:      ├─── RD1 ───┤├─── RD2 ───┤├─── RD3 ───┤
           ↑
           段1 写完（WR1=4.2ms），扫描启动
           WR2 和 RD1、WR3 和 RD2 各自重叠
```

**最后一像素出现**：扫描从段1 写到 GRAM 那一刻启动，走完整帧到段3 底部。

```
T_B = T_fb_swap + T_seg_transfer + T_panel_scan
    = 8.3 + 4.2 + 16.7
    = 29.2ms ≈ 1.8 帧
```

**为什么只有 `T_seg_transfer`（首段）而非 ×3**：段2、段3 的写入与扫描重叠，不额外占时间。

**成立的前提**：

```
每个后续段的写入必须在前一段扫描完成前结束，否则扫描空等:

WR2 写完 (4.2ms) < RD1 扫完 (5.6ms) ✓
WR3 写完 (4.2ms) < RD2 扫完 (5.6ms) ✓

即: T_seg_transfer ≤ T_seg_scan
   4.2ms ≤ 5.6ms ✓
```

若该条件不满足（例如 DSI 带宽不足、`T_seg_transfer` 变大），扫描会等传输完成，退化为串行。

### 4.4 三种方式对比

| 方式 | 公式 | 约束 | 延迟 | 需要的硬件支持 |
|------|------|------|------|-------------|
| A 串行 | `T_fb + 3×T_seg_transfer + 3×T_seg_scan` | 无 | 37.7ms (2.3帧) | 最基础的单 Bank GRAM |
| B 流水线 | `T_fb + T_seg_transfer + T_panel_scan` | `T_seg_transfer ≤ T_seg_scan` | 29.2ms (1.8帧) | 双 Bank 或双端口 RAM |
| 理想参考 | `T_fb + T_panel_scan` | 传输带宽无限 | 25ms (1.5帧) | 等于 Video Mode 延迟，物理上不可达 |

## 5. TE 信号

### 5.1 TE 频率由 GRAM 容量决定

TE 信号的含义：**"一段 GRAM 已被消费完，可以写下一段"**。

| GRAM 容量 | 帧内写几段 | TE 频率 | TE 周期 | TE 在什么时候拉低 |
|-----------|----------|---------|---------|----------------|
| 全帧 | 1 | 60 Hz | 16.7ms | 整帧扫完 |
| 1/2 帧 | 2 | 120 Hz | 8.3ms | 每半帧扫完 |
| 1/3 帧 | 3 | 180 Hz | 5.6ms | 每 1/3 帧扫完 |

1/3 RAM 下，`set_tear_on()` 需要配 `VHBLANK` 模式，`set_tear_scanline()` 精确定位三个段边界。

### 5.2 TE 对延迟的影响

全 GRAM 每帧等 1 次 TE，指令模式抖动只发生 1 次。1/3 RAM 每帧等 3 次 TE，**3 次的中断延迟全部叠加到总延迟**。Host CPU 中断延迟越大，这个放大效应越明显。

---

## 6. 总对比

以 1080×1920 @ 60fps, 4-lane @ 1Gbps, 24bpp 为例：

| 模式 | 公式 | 数值 | 帧数 |
|------|------|------|------|
| **Video Mode** | `T_fb + T_panel_scan` | 25ms | 1.5 帧 |
| **CMD 全 GRAM（边收边扫）** | `T_fb + max(T_transfer, T_scan) + T_te` | ~33ms | 2 帧 |
| **CMD 全 GRAM（收完再扫）** | `T_fb + T_transfer + T_scan + T_te` | ~46ms | 2.8 帧 |
| **CMD 1/3 RAM（流水线）** | `T_fb + T_seg_transfer + T_panel_scan` | 29ms | 1.8 帧 |
| **CMD 1/3 RAM（串行）** | `T_fb + 3×(T_seg_transfer + T_seg_scan)` | 38ms | 2.3 帧 |

---

## 7. 向 Panel 原厂要的关键参数

| 参数 | 用途 | 风险等级 |
|------|------|---------|
| GRAM 容量（全帧/半帧/1/3帧/无） | 决定分段数和 TE 频率 | 致命 |
| 是否支持边收边扫 / 双 Bank | 决定传输和扫描能否重叠 | 高 |
| TE 信号最小间隔 | 1/3 RAM 下决定分段传输速率上限 | 高 |
| TE 模式（VBLANK/VHBLANK）和 scanline 位置 | 决定分段的精确边界 | 中 |
| Panel 行扫描方向和时间 | 决定 `T_panel_scan` 的精确值 | 低 |
