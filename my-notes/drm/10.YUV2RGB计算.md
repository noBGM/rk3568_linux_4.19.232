# YUV→RGB 颜色空间转换：从原理到系数

> 从色彩学第一性原理推导 BT.601/BT.709 矩阵，再到 RGA 硬件寄存器的 `.coef`/`.offset` 真实数据，读完即懂。

---

## 1. 为什么要有 YUV

历史原因：1950 年代彩色电视出现时，必须兼容已有的黑白电视机。

- 黑白电视只接收一个**亮度信号 Y**（Luma）。
- 彩色电视需要额外两个**色度信号 U、V**（Chrominance），承载在副载波上。
- 黑白电视忽略 UV，只看 Y，正常显示黑白画面；彩色电视从 Y+UV 恢复 RGB。

这就是"兼容性分离"——把 RGB 三色信号拆成 **1 个亮度 + 2 个色差**。

---

## 2. 数学框架：RGB ↔ YUV 是怎么算的

### 2.1 核心思路

人眼对绿色最敏感（~60% 亮度贡献），对红色次之（~30%），对蓝色最不敏感（~10%）。所以 Y 是 R、G、B 的加权和：

```
Y = Wr × R + Wg × G + Wb × B      （Wr + Wg + Wb = 1）
```

> **Y 是"亮度（Luminance）"，不是"白色成分"。**

Wr + Wg + Wb = 1 只保证：当 R=G=B 时（灰/白/黑这些无彩色），Y 等于像素值本身。纯白 (255,255,255) → Y=255，中灰 (128,128,128) → Y=128，纯黑 (0,0,0) → Y=0。

但权重不同是因为**人眼对不同颜色的感知亮度差异巨大**。以 BT.709 为例（Wr=0.2126, Wg=0.7152, Wb=0.0722）：

| 纯色 | RGB 值 | Y 计算 | 感知亮度 |
|------|--------|--------|---------|
| 纯绿 | (0, 255, 0) | 0.7152 × 255 = **182** | 很亮 |
| 纯红 | (255, 0, 0) | 0.2126 × 255 = **54** | 中等偏暗 |
| 纯蓝 | (0, 0, 255) | 0.0722 × 255 = **18** | 非常暗 |

三个颜色的 RGB 数值都是 255，但 Y 差了 **10 倍**。你在屏幕上并列显示纯蓝和纯绿，绿色那块明显亮得多。Y 就是对这种生理现象的数学建模——它模拟的是人眼的亮度感知，不是物理光功率。

有了 Y 之后，色差信号定义为：

```
U = Cb = (B − Y) / (2 × (1 − Wb))    ← 蓝色差
V = Cr = (R − Y) / (2 × (1 − Wr))    ← 红色差
```

**关键点：Wr、Wg、Wb 的值取决于你用的是哪个色彩标准。**

### 2.2 从 RGB 基色推导权重

每个色彩标准定义了自己的 R、G、B 三基色和白点的 CIE xy 色坐标：

| 标准 | R 基色 (x,y) | G 基色 (x,y) | B 基色 (x,y) | 白点 D65 (x,y) |
|------|-------------|-------------|-------------|----------------|
| BT.601 (SDTV) | (0.640, 0.330) | (0.290, 0.600) | (0.150, 0.060) | (0.3127, 0.3290) |
| BT.709 (HDTV) | (0.640, 0.330) | (0.300, 0.600) | (0.150, 0.060) | (0.3127, 0.3290) |

注意 BT.601 和 BT.709 的 G 基色 y 坐标虽然都是 0.600，但 x 不同（0.290 vs 0.300）——这意味着两者的**绿色定义不同**，因此推导出的权重也不同。

由色匹配方程可以解出：

```
BT.601:  Wr=0.299,  Wg=0.587,  Wb=0.114
BT.709:  Wr=0.2126, Wg=0.7152, Wb=0.0722
BT.2020: Wr=0.2627, Wg=0.6780, Wb=0.0593
```

**这就是 BT.601 和 BT.709 所有差异的根源——绿色对人眼亮度的贡献权重不同（0.587 vs 0.7152）。**

## 3. YUV→RGB 逆变换公式推导

### 3.1 数学推导

从正变换出发：

```
Y  = Wr×R    + Wg×G    + Wb×B
Cb = (B − Y) / (2×(1−Wb))
Cr = (R − Y) / (2×(1−Wr))
```

求逆（代数推导略去中间步骤），得：

```
R = Y + Cr × 2×(1−Wr)
G = Y − Cb × 2×(1−Wb)×Wb/Wg − Cr × 2×(1−Wr)×Wr/Wg
B = Y + Cb × 2×(1−Wb)
```

### 3.2 代入 BT.709 的 Wr/Wg/Wb

```
Wr = 0.2126,  Wg = 0.7152,  Wb = 0.0722

2×(1−Wr) = 2×0.7874 = 1.5748
2×(1−Wb) = 2×0.9278 = 1.8556

R = Y + 1.5748 × Cr
G = Y − 1.8556×0.0722/0.7152 × Cb − 1.5748×0.2126/0.7152 × Cr
  = Y − 0.1873×Cb − 0.4681×Cr
B = Y + 1.8556 × Cb
```

这就是 BT.709 的浮点逆变换矩阵。但代码里看到的 1192、1836、-218 等整数是怎么回事？往下看。

## 4. Limited Range（限制范围）：又一个关键变量

### 4.1 问题

计算机 RGB 范围是 [0, 255]（Full Range）。但广播电视标准中，Y 和 UV 不是：

```
Limited Range:
  Y:  [16, 235]      （16=黑, 235=白，留了余量给 overshoot）
  UV: [16, 240]      （128=无色/灰）
```

### 4.2 映射关系

在 YUV→RGB 计算前，需要先把 limited range 值"拉伸"到 full range：

```
Y_full  = (Y_limited − 16) × 255/(235−16) = (Y − 16) × 1.1644
Cb_full = (Cb − 128) × 255/(240−16)       = (Cb − 128) × 1.1384
Cr_full = (Cr − 128) × 255/(240−16)       = (Cr − 128) × 1.1384
```

把这个拉伸和颜色矩阵合并，就得到了**最终的"一体化"转换系数**。

---

## 5. BT.709 Limited Range → RGB 的完整浮点推导

把 range 拉伸代入 BT.709 矩阵：

```
Y'  = 1.1644 × (Y − 16)
Cb' = 1.1384 × (Cb − 128)
Cr' = 1.1384 × (Cr − 128)
```

代入 R 通道：

```
R = Y' + 1.5748 × Cr'
  = 1.1644×(Y−16) + 1.5748×1.1384×(Cr−128)
  = 1.1644×Y − 1.1644×16 + 1.7927×Cr − 1.7927×128
  = 1.1644×Y + 1.7927×Cr + (−18.630 − 229.466)
  = 1.1644×Y + 1.7927×Cr − 248.10
```

同理 G 通道：

```
G = Y' − 0.1873 × Cb' − 0.4681 × Cr'
  = 1.1644×(Y−16) − 0.1873×1.1384×(Cb−128) − 0.4681×1.1384×(Cr−128)
  = 1.1644×Y − 0.2132×Cb − 0.5329×Cr + (−18.630 + 27.264 + 68.224)
  = 1.1644×Y − 0.2132×Cb − 0.5329×Cr + 76.86
```

B 通道：

```
B = Y' + 1.8556 × Cb'
  = 1.1644×(Y−16) + 1.8556×1.1384×(Cb−128)
  = 1.1644×Y + 2.1124×Cb + (−18.630 − 270.35)
  = 1.1644×Y + 2.1124×Cb − 288.98
```

汇总浮点矩阵：

```
⎡R⎤   ⎡1.1644   0.0000   1.7927⎤ ⎡Y ⎤   ⎡−248.10⎤
⎢G⎥ = ⎢1.1644  −0.2132  −0.5329⎥ ⎢Cb⎥ + ⎢  76.86⎥
⎣B⎦   ⎣1.1644   2.1124   0.0000⎦ ⎣Cr⎦   ⎣−288.98⎦
```

## 6. 定点化：为什么是 1192、1836、2163

硬件不能算浮点，用**定点数**（Q10.0 格式）：所有系数 ×1024（即右移 10 位 = ÷1024）。

```
1.1644 × 1024 ≈ 1192     ← Y 对 RGB 三通道的共同系数
1.7927 × 1024 ≈ 1836     ← Cr 对 R 的系数（红）
−0.2132 × 1024 ≈ −218    ← Cb 对 G 的系数
−0.5329 × 1024 ≈ −546    ← Cr 对 G 的系数
2.1124 × 1024 ≈ 2163     ← Cb 对 B 的系数（蓝）
```

所以矩阵变成：

```
R = (1192 × Y +    0 × Cb + 1836 × Cr + offset_R) / 1024
G = (1192 × Y + (−218) × Cb + (−546) × Cr + offset_G) / 1024
B = (1192 × Y + 2163 × Cb +    0 × Cr + offset_B) / 1024
```

---

## 7. offset 的来历

上面算出的浮点 offset 是 −248.10、+76.86、−288.98。定点化（×1024）后：

```
−248.10 × 1024 ≈ −254054
   76.86 × 1024 ≈  78705
−288.98 × 1024 ≈ −295920
```

但在 RGA 硬件中，实际写入的 offset 是 **256, 2048, 2048**——和上面的理论值不同。

这是因为 RGA 硬件**内部用 12-bit 流水线**，UV 输入也是 unsigned 格式（0-255），系数用 Q10 格式（÷1024），而 offset 的编码方式利用了二进制的截断特性——它不是一个简单的 "加 offset 再除以 1024"，而是：

```
result = ((coef × yuv) >> 10) + offset_encoded
```

具体编码细节依赖于硬件实现，不同 IP（RGA2/RGA3/VOP）有差异。但**数学本质相同**：offset 的作用就是补偿 Y=16、Cb/Cr=128 时 RGB 应为 (0,0,0)。

可以通过黑点代入验证：Y=16, Cb=128, Cr=128 时，矩阵乘积累加 offset 后 ÷1024 → clip → 0。

## 8. 完整数值示例

使用你的 `.coef` 和 `.offset`，走一遍实际像素：

```
.coef   = {1192, 0, 1836, 1192, -218, -546, 1192, 2163, 0}
.offset = {256, 2048, 2048}
```

取 Y=180, Cb=90, Cr=200：

### Step 1 — 矩阵乘法

```
R_sum = 1192×180 +    0×90 + 1836×200 = 214560 + 0 + 367200 = 581760
G_sum = 1192×180 + (−218)×90 + (−546)×200 = 214560 − 19620 − 109200 = 85740
B_sum = 1192×180 + 2163×90 +    0×200 = 214560 + 194670 + 0 = 409230
```

### Step 2 — 加 offset

```
R_sum + 256  = 582016
G_sum + 2048 = 87788
B_sum + 2048 = 411278
```

### Step 3 — 右移 10 位 (÷1024)

```
R = 582016 / 1024 ≈ 568.38 → 568
G =  87788 / 1024 ≈  85.73 →  85
B = 411278 / 1024 ≈ 401.64 → 401
```

### Step 4 — clip 到 [0, 255]

```
最终 RGB = (255, 85, 255)     ← 一个偏紫的像素
```

## 9. BT.601 vs BT.709 的直观对比

| | BT.601 (SDTV) | BT.709 (HDTV) |
|---|---|---|
| Y 权重 (Wr,Wg,Wb) | 0.299, 0.587, 0.114 | 0.2126, 0.7152, 0.0722 |
| U→R 系数 | 0 | 0 |
| V→R 系数 (×1024) | **1634** | **1836** |
| U→G 系数 (×1024) | **−401** | **−218** |
| V→G 系数 (×1024) | **−832** | **−546** |
| U→B 系数 (×1024) | **2066** | **2163** |

差异根源：BT.709 的绿色对亮度贡献更大 (0.7152 > 0.587)，所以色差信号对 G 通道的影响更小（−218 的绝对值 < −401 的绝对值）。

如果拿 BT.601 的矩阵去解码 BT.709 编码的视频，绿色通道会被过度修正，画面偏绿或偏品红。

## 10. 寄存器视角：coef 和 offset 如何写入硬件

以 RGA2 为例，`full_csc_t` 结构体展开到硬件寄存器：

```
CSC_00 ← coe_y.r_v   (1192)    ─┐
CSC_01 ← coe_y.g_y   (0)        ├─ R 通道: coe_y 这一行
CSC_02 ← coe_y.b_u   (1836)    ─┘
CSC_OFF0 ← coe_y.off (256)

CSC_10 ← coe_u.r_v   (1192)    ─┐
CSC_11 ← coe_u.g_y   (-218)     ├─ G 通道: coe_u 这一行
CSC_12 ← coe_u.b_u   (-546)    ─┘
CSC_OFF1 ← coe_u.off (2048)

CSC_20 ← coe_v.r_v   (1192)    ─┐
CSC_21 ← coe_v.g_y   (2163)     ├─ B 通道: coe_v 这一行
CSC_22 ← coe_v.b_u   (0)       ─┘
CSC_OFF2 ← coe_v.off (2048)
```

注意命名约定：`coe_y`/`coe_u`/`coe_v` 虽然叫 "Y 系数/U 系数/V 系数"，但实际含义是**输出通道的矩阵行**（分别在算 R/G/B），而不是输入通道列。这是 RGA 驱动写代码时的历史命名。

每个像素流过一个 3×3 MAC（乘累加器），三行并行计算，再加 offset 右移 10 位，结果送给下一级（缩放/图层混合）。

## 11. 总结

```
              BT.709 基色  →  Wr/Wg/Wb  →  浮点 3×3 矩阵
                                                ↓
                                          Limited Range
                                          拉伸合并进去
                                                ↓
                                          ×1024 定点化
                                                ↓
                                .coef = {1192, 0, 1836, ...}
                                .offset = {256, 2048, 2048}
                                                ↓
                              RGB = (Matrix × YUV + Offset) >> 10
                                                ↓
                                         clip [0,255]
                                                ↓
                                         显示在屏幕上
```
